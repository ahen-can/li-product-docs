## Notes on this run

- 2 products per insurer were spot-checked by hand (UIN in the PDF, product name and description line on the first pages), plus an automated audit of every stored file: product name on the first 4 pages, no CIS, BI, rate table, appendix or rider document, and the UIN code present (text or OCR).
- Description lines are taken from the first 3 pages (layout text, then plain text, then OCR at 400/200 dpi) with whitespace collapsed. Some PDFs drop the "ti" ligature ("Non-Par cipa ng"); those are listed above and should be read as "Participating".
- `features_keyword_hits` is a keyword presence scan only, not a verified feature.
- During the run `index.csv` was emptied once by a crashed re-extraction. It was rebuilt from the results file and the stored files: hashes, sizes and page counts were recomputed, and it matched the already-committed Bharti rows field for field. Index writes are now atomic. `scripts/check_consistency.py` confirms every file in `docs/` has an index row and every row's files exist.
- A second pass replaced 70 stored leaflets/one-pagers and 10 fallback policy documents with full brochures where the site has them.
- Helper scripts added: `find_product_pages.py` (sitemap → product page, opened before writing), `map_pages_by_uin.py` (LIC tables), `set_product_page.py`, `add_note.py`, `stage_insurers.py` (one-insurer commits), `check_consistency.py`, `build_coverage.py`, `build_summary.py`.
